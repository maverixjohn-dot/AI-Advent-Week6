# День 30. Локальная LLM как приватный сервис

## Результат

Развёрнут приватный AI-сервис на домашнем сервере: локальная LLM с HTTP API
(OpenAI-совместимый) и чат-интерфейсом через Telegram-бота. Многопользовательский
доступ по whitelist, rate limiting, управление контекстом, администрирование через
команды бота.

## Архитектура

```
Пользователи (интернет, whitelist)
        ↕ Telegram Bot API
Telegram-бот (Python, aiogram 3, SQLite)
  whitelist и роли · rate limit · очередь (глобальный лимит 4)
  история диалогов + скользящее окно контекста · системный промпт
  параметры генерации · статистика · обработка ошибок LLM
        ↕ HTTP 127.0.0.1:1234, Bearer-токен
LM Studio 0.4.x (llama.cpp) — Qwen3.8-27B
  continuous batching, 4 слота, unified KV cache
```

Разделение ответственности: LM Studio — слой инференса (загрузка модели,
параллелизм, auth на API); бот — всё пользовательское (доступ, лимиты, память
диалогов, настройки). Дополнительные слои (MCP, отдельный гейтвей) на этапе
проектирования рассматривались и отвергнуты как избыточные.

## Конфигурация

**Железо:** десктоп, AMD Ryzen 9 9950X3D, 64 ГБ RAM, NVIDIA RTX 5070 Ti 16 ГБ,
Windows 11 (WDDM).

**Модель:** Qwen3.8-27B, квант Unsloth Dynamic IQ3_S (12,97 ГБ). Гибридная
архитектура (Gated DeltaNet + полный attention на каждом 4-м слое), reasoning,
нативный контекст 262K. Зрительная часть (mmproj) отключена — бот текстовый.

**LM Studio (финальная рабочая точка):**

| Параметр | Значение |
|---|---|
| Context Length | 36864 (пул, 4 слота, unified KV cache) |
| Max Concurrent Predictions | 4 (очередь сверх лимита) |
| K/V Cache Quantization | q8_0 |
| Flash Attention | on |
| Speculative Decoding | MTP (приёмка черновика 50–62%) |
| GPU Offload | 60 из 65 слоёв |
| Context Checkpoints | 8 |
| Evaluation Batch Size | 512 |
| API Tokens (auth) | on |
| Serve on local network | off (в проде; включается только для сетевого теста) |
| JIT / auto-unload | off (модель горячая, Keep Model in Memory) |
| Свободная VRAM при загруженной модели | ~1,1 ГиБ |

**Бот** (Python 3.14, aiogram 3.31, httpx, aiosqlite): строгий whitelist по
числовым Telegram ID; rate limit 5 сообщений/мин и 1 активная генерация на
пользователя; глобальный семафор 4 (соответствует слотам сервера); история в
SQLite, скользящее окно 6400 токенов (оценка chars/3); max_tokens 2048.
Админ-команды: `/allow`, `/ban`, `/users`, `/set_system`, `/set_params`,
`/set_context`, `/set_rate`, `/set_reasoning`, `/settings`, `/stats`, `/health`,
`/reset [id]`.

## Ключевые инженерные находки

1. **WDDM-пейджинг — главный риск конфигурации «впритык».** При занятости VRAM
   ≥ 15,8/16 ГБ Windows молча вытесняет память модели в системную RAM: скорость
   деградировала 20,5 → 8,8 → 2,6 → 0,4 ток/с, перезапуск LM Studio не помогал.
   Диагноз ставится по nvidia-smi (свободно < 0,5 ГиБ). Лечение — запас ≥ 1 ГиБ:
   снижение GPU offload до 60/65 слоёв. После исправления: одиночный поток
   29,5 ток/с, 4 потока — агрегат 68,2 ток/с.
2. **Оценщику памяти LM Studio нельзя доверять**: занижал на ~1,5 ГБ
   (показывал 13,64–14,69 ГБ при фактических ~15,8). Панель «Size 12.04 GB»
   показывает размер файла весов, а не потребление VRAM. Источник истины —
   nvidia-smi.
3. **Reasoning-модели могут вернуть пустой ответ**: thinking-токены входят в
   max_tokens; при малом лимите получаем `finish_reason=length, content=""`
   (512/512 токенов ушло в рассуждение). Меры: max_tokens 2048, Reasoning Budget
   Message на сервере, обработка пустых ответов в боте.
4. **MTP speculative decoding работает**: приёмка черновика 50–62%, ускорение
   заметно и в одиночном потоке, и под нагрузкой.
5. **LCP prefix caching**: запросы с общим префиксом (единый системный промпт)
   переиспользуют KV-кэш — повторные обращения дешевле.
6. **Параллелизм в LM Studio 0.4.x** — Max Concurrent Predictions + unified KV;
   запросы сверх слотов встают в очередь. Per-user rate limiting на сервере
   отсутствует — реализуется в боте.
7. **Гибридная архитектура (DeltaNet)**: KV-кэш маленький (полный attention
   на 1/4 слоёв), но рекуррентное состояние не поддерживает плавное вытеснение —
   управление контекстом выполняется только на стороне бота (скользящее окно).
8. **Префилл дорогой**: 26249 токенов промпта ≈ 17–20 с (~1300–1500 ток/с).
   Следствие для UX: длинные истории замедляют именно старт ответа; бюджет
   контекста 6400 токенов на пользователя — разумный компромисс (~4–5 с префилла).

## Оценка ёмкости сервиса

Комфортно: 3–4 одновременных активных пользователя (per-stream ~18 ток/с при
полной загрузке слотов). Сверх того — очередь с ростом latency. Для большего
числа пользователей — модель меньшего калибра (больше слотов, выше скорость)
или GPU с большим VRAM.

## Известные ограничения

- Приватность — от внешних провайдеров; админ хоста видит логи и базу истории.
- Оценка токенов в боте грубая (chars/3), без точного токенизатора.
- Нет стриминга ответов (осознанное решение v1).
- Сервис делит GPU с десктопом: тяжёлые GPU-приложения съедают запас VRAM.
- Конфигурация привязана к 16 ГБ VRAM; на другой карте рабочую точку нужно
  пересчитывать (формула: запас ≥ 1 ГиБ сверх модели).
