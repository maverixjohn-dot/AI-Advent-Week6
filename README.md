# Локальная LLM — оптимизация (LM Studio + Flet)

Веб-приложение для оптимизации локальной модели под конкретную задачу:
настройка параметров генерации, пресеты «до/после», сравнение ответов
и скорости, журнал всех запросов.

**Стек:** Python + Flet (веб), LLM — LM Studio (`qwen3.8-27b`, GGUF).

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

Откроется `http://127.0.0.1:8550` (хост жёстко задан в `main.py` — только
локальный доступ). Страницы: **/** — чат, **/admin** — администрирование,
**/logs** — логи.

Перед запуском: в LM Studio запустите сервер — **Developer → Start Server**
(по умолчанию `http://127.0.0.1:1234`).

> При первом веб-запуске Flet один раз скачивает пакет `flet-web` — нужен
> интернет. Если он не поставился автоматически: `pip install flet-web`.

## Квантование qwen3.8-27b — что доступно

Квантование **уже применено**: модель загружена как GGUF **IQ3_S** (~13 GB).
Это свойство файла, а не параметр API — сменить квант «на лету» нельзя,
нужно скачать другой файл той же модели в LM Studio:

| Квант | Размер (≈) | Качество | Когда брать |
|---|---|---|---|
| IQ3_S (текущий) | 13 GB | Заметная деградация | Только при жёстком лимите памяти |
| **Q4_K_M / UD-Q4_K_XL** | 16–17 GB | Хороший баланс | **Рекомендуется** |
| Q5_K_M | 19–20 GB | Почти без потерь | Если VRAM/RAM позволяет |
| Q8_0 | ~28 GB | Максимум | Для эталонных замеров |

Скорость генерации между IQ3_S и Q4_K_M почти одинаковая (упор в память),
поэтому переход на Q4_K_M — самый дешёвый шаг повышения качества.
Текущий квант виден в приложении: **Администрирование → Проверить соединение**.

## Методика сравнения «до/после»

1. **Администрирование → Пресеты**: посмотрите состав пресетов
   «до оптимизации» (temp=1.0, без промпта, 512 токенов, контекст 4096) и
   «после оптимизации» (temp=0.2, структурирующий промпт, 2048 токенов,
   контекст 16384, seed=42).
2. **Чат → включите «Сравнение до/после»** и отправьте типичный для вашей
   задачи запрос. Один запрос уйдёт дважды — ответы и метрики
   (время, токены, ток/с, temp) появятся рядом.
3. Оценивайте: структурированность и полноту ответа (512 токенов «до»
   часто обрезают мысль), стабильность формата, скорость (ток/с зависит от
   max_tokens слабо, от кванта — сильно).
4. Подберите свои значения на странице администрирования и сохраните —
   они применяются ко всем новым запросам.
5. Все запросы и метрики пишутся в **Логи** (`data_files/logs.jsonl`) —
   по ним считается средняя скорость до/после.

## Что где настраивается

| Параметр | Где | Эффект |
|---|---|---|
| Системный промпт | Администрирование | Главный рычаг качества под задачу |
| temperature / top_p | Администрирование | 0.1–0.3 для фактических ответов, 0.7+ для генерации идей |
| max_tokens | Администрирование | Лимит длины ответа |
| context_window | Администрирование | Обрезка истории в приложении; реальный предел — в LM Studio при загрузке модели |
| seed | Администрирование | Воспроизводимость ответов при сравнении |
| Квантование | LM Studio (файл модели) | Качество/память; см. таблицу выше |
| GPU offload, threads | LM Studio | Скорость; из приложения не управляется |

## Структура

```
main.py            — точка входа (host=127.0.0.1, port=8550, веб)
core/settings.py   — настройки + пресеты до/после (data_files/settings.json)
core/llm.py        — клиент LM Studio, замеры, обрезка истории под контекст
core/logger.py     — JSONL-журнал (data_files/logs.jsonl)
ui/theme.py        — тёмная тема (стандарт ui-2026-minimal: 1 акцент, сетка 8px)
ui/app.py          — роутинг и навигация
ui/chat_page.py    — чат + сравнение до/после
ui/admin_page.py   — настройки, пресеты, проверка соединения, квант
ui/logs_page.py    — просмотр и очистка журнала
tests/test_app.py  — headless-тесты (нужен запущенный сервер на 1234 или mock)
```

## Известные ограничения

- История чата хранится в памяти процесса — при перезапуске очищается
  (логи при этом сохраняются).
- Потребление RAM/VRAM самой моделью из приложения не измеряется — это
  показывает LM Studio / диспетчер задач. Приложение замеряет время ответа
  и ток/с.
- `response_format` не используется — локальный сервер его отклоняет
  (ошибка 400 `response_format.type must be 'json_schema' or 'text'`).
- Base URL нормализуется автоматически: `…/v1/qwen3.8-27b` → `…/v1`.
- Если в LM Studio включён **Developer → Server Settings → Require API Key**,
  запросы без ключа получают `401 Unauthorized`. Введите ключ в поле
  «API-ключ» на странице администрирования (уходит заголовком
  `Authorization: Bearer …`) или отключите опцию в LM Studio. Ключ в логи
  не пишется (в журнале маскируется).
